The Problem

AI 的失忆症，是设计问题

每次对话结束，一切归零。上周踩过的坑，这周原样再踩一遍——因为绝大多数 AI 客户端，压根没有"记忆"这个位置。

没有 Mindbox 的时候

  • 昨天聊了一下午的项目，今天它完全不认识你
  • 踩过的坑重复踩，同一处错反复讲
  • 把整段聊天历史一直背着，上下文很快爆掉
  • 记忆服务把你的笔记传上云，数据不是你的了

接上 Mindbox 之后

  • 开新会话先读一遍记忆，它还记得你
  • 错误案例、技能配方沉淀下来，不再重复劳动
  • 状态随手写出去再读回来，上下文压力小得多
  • 全是硬盘上的普通文件，记事本就能打开改
Three Layers

记忆分三层，各管一段

短期是便签纸，长期是资料柜，永久是刻在石头上的。分层的目的很实际：让"还没定论"和"已经确认"的东西分开住，AI 就不会把猜测当成事实。

LAYER 01

短期记忆

SESSION · 便签纸

当前会话的工作台。每个会话单独一个文件夹，记着这一轮在干什么、做到哪了、有什么中间结论、还剩什么没做。会话结束就冻结。

会话.json + 上下文.md
LAYER 02

长期记忆

DRAFTS · 资料柜

过渡区，放"可能有用但还没定论"的东西。分 9 类：任务记录、技能配方、资料摘要、用户偏好、待验证三元组、错误案例、情绪历史、外部大脑效果、项目上下文。

9 个分类 · 每条带置信度与来源
LAYER 03

永久记忆

KNOWLEDGE GRAPH · 刻在石头上

只放已经确认的事实，以三元组形式存：主语 —[关系]→ 宾语，构成一张知识图，支持顺着关系往下找。存了"exfat 不支持符号链接"，以后问起符号链接，能沿着关系把相关的都捞出来。

条目 + triples.json
Confidence Gate

置信度当闸门，挡住 AI 随口瞎编

写一条记忆时要报一个 0–100 的把握度，系统按这个分流。不敢肯定就别往永久里塞——这是整套设计里最实用的一条规则。

88 / 100
0 · 不收60 · 待验证85 · 永久100
PASSED

写入永久记忆

把握度足够高，直接进知识图，成为长期可用的事实。

add_triple(confidence=88) → 永久记忆/triples.json
9 Tools

只给 AI 9 个工具，不多

工具越多，AI 越容易挑错、越浪费上下文。凡是能被别的工具覆盖的，或者你打开文件夹就能看的，一律没做——中间版本曾经有 17 个，后来砍掉了 8 个。

memory_overview看三层记忆的总体情况
session_open开一个会话（也返回已有快照，等于读）
session_update更新会话进度
session_close结束会话，可把结论转进长期记忆
memory_add写一条长期 / 永久条目
memory_query检索记忆
memory_delete删一条（纠错用）
add_triple写三元组，按置信度自动分流
query_graph在知识图上检索
Quick Start

三步接进去，不用装任何东西

没有安装包，不需要编译。整个项目只用 Python 标准库，零第三方依赖——不需要 pip install，不需要虚拟环境，不需要数据库。

1

拿到代码

克隆仓库，或者直接下载 ZIP 解压到任意目录。真正必需的只有两个文件：server.py 和 memory_store.py，哪怕只拷这两个出去也能跑。

bash 
# 克隆仓库
git clone https://github.com/ShieldDog-ACE/Mindbox_Note.git
2

让 AI 客户端认识它

在客户端的 MCP 设置里加一段配置。command 一定要写绝对路径，客户端的工作目录不固定。

mcp.json 

          

        

      


      

        
3

        

          
先自己确认服务是好的

          
这一步不需要任何客户端配合。正常会打印服务器名、版本、工具数量，以及三层记忆当前各有多少条。

          

            
bash
              

            
python3 /你的路径/Mindbox-MCP/server.py --check

          

          
接好之后不用操心调工具，AI 会自己用。你只要正常说话：

          「记住：我的项目在 /x/y」·「上次那个 bug 怎么修的」·「今天先到这」

        

      

    

  







  

    

      
Why Trust It

      
数据主权，是它唯一的设计立场

    

    

      

        📁
        
一切皆纯文件

        
JSON 存结构，Markdown 存给人看的摘要。记事本打开就能看、能改、能删，改完立刻生效，不用重启。不存在"导不出来"这回事。

      

      

        🔌
        
零依赖

        
只用 Python 标准库的 7 个模块。不需要 pip、不需要虚拟环境、不需要 Node.js、不需要数据库。依赖越少，三年后它还能跑的概率越大。

      

      

        🔒
        
完全离线

        
stdio 本地进程，不开端口、不联网、不上传。它本身不是 AI，也不碰任何模型权重——真正动脑子的是你的 AI，它只负责记住。

      

      

        🔍
        
检索是真的能搜到

        
中英文都能搜，不用装分词库。查询词和库内内容都切一遍，按重合度乘置信度排序——"打包 数据目录 笔记丢失"这种组合查询，能把最相关的那条错误案例排到最前面。

      

      

        🛡️
        
三个根文件夹删不掉

        
短期 / 长期 / 永久记忆是系统自带根目录，删除操作在工具层面就被拦住，每次启动还会自检、缺了自动重建。记忆系统最怕的不是写错，是被清空。

      

      

        🧩
        
接进任何客户端

        
标准 MCP 协议（JSON-RPC 2.0 / stdio），手写的协议层没引官方 SDK。Trae、Cursor、Claude Code、CodeBuddy 都能接，配置就是一段 JSON。

⚠️ 一些实话

      
知道这些再决定用不用，比看到一堆好话强。以下是当前版本的实际情况：

      
    
        
  1. 没有自动升级机制。原设计的"引用超 100 次、成功率超 90% 就升入永久"门槛实际中基本达不到，功能暂时撤掉。想让某条进永久，用 add_triple 以 85 分以上写一遍。
    2. 
        
  2. 并发写入没有加锁。单个 AI 使用没影响；同时挂多个客户端且同一秒写同一条记忆，理论上可能互相覆盖。
    3. 
        
  3. 中文分词是自己写的（单字 + 双字），不是 jieba。好处零依赖，坏处召回率不如专业分词库。
    4. 
        
  4. 只在 Trae 上做过真机接入测试。Cursor、Claude Code、CodeBuddy 的配置都给了，但没实地跑过。
    5. 
        
  5. 没有鉴权。因为它是本地 stdio 进程，只有本机能碰。做成 HTTP 远程服务的话必须自己补 Token。
    6.
