# 任务书:Mindbox —— AI 记忆笔记软件

> 版本 v0.3 · 2026-09-20 · 状态:开发中
> 一句话定位:本地优先的 AI 原生笔记软件,前端交互参考 Obsidian,

## 0.1 接口预留原则(为后续修改留缝)

1. REST API 统一前缀 `/api/v1`,版本化,升级不破坏旧调用
2. API 层(api/)只做参数校验,逻辑全在服务层(services/)——记忆引擎、检索引擎可整体替换
3. 记忆升降级阈值、衰减参数集中在 config,不散落硬编码
4. Electron 主进程拉起后端的命令可被环境变量覆盖(`MINDBOX_PYTHON` / `MINDBOX_BACKEND_CMD`),为 PyInstaller sidecar 预留
5. MCP 工具采用注册表模式(M3),新增工具零侵入

## 1. 产品定位

- **Mindbox 本身不是 agent**:它是一款笔记软件 + 记忆库,不做内置 AI 对话
- **前端是给人看的**:布局、交互、快捷键对标 Obsidian,服务于人类用户
- **MCP 是它对外的唯一 AI 接口**:外部 agent(Claude Code、Cursor、任意 MCP 客户端)
  通过 MCP 连接进来,读写笔记库与三层记忆;Mindbox 只做数据和工具的提供方
- 运行在本地,笔记库 = 纯文件(无数据库锁定,数据主权归用户)
- 内建三层记忆引擎:短期(会话)→ 长期(过渡区)→ 永久(知识图)

## 2. 三层记忆架构(核心)

### 2.1 短期记忆(Working Memory)—— 会话作用域

| 项 | 说明 |
|---|---|
| 生命周期 | 每个新对话创建一份,只在**本会话内**读写,不跨会话 |
| 内容 | 上下文摘要、任务进度(可累积)、中间结论、本轮待办 |
| 目的 | 给模型一个紧凑的"状态快照",避免上下文爆满导致模型变傻 |
| 存储 | `memory/short/{session_id}.json`(结构化)+ 可选同名 `.md` 摘要 |
| 结束处理 | 会话关闭 → 结算:有价值的条目转入长期记忆,其余随会话冻结 |

### 2.2 长期记忆(Transition Zone)—— 过渡区

存放"不一定有用,但可能有用"的内容,以及情绪与可信度信息。
每条记录携带元数据:**时间、来源、分类、置信度(0-100)、引用次数、成功/失败次数、衰减系数**。

九类条目与升降级规则:

| 类别 | 具体内容 | 示例 | 后续处理 |
|---|---|---|---|
| 近期任务记录 | 最近 1-4 周完成或失败的任务 | "处理销售表格,用时 1.2 秒" | 高频成功→升级永久;失败→转 error_case |
| 新学技能/配方 | 从外部大脑或资料学到、尚未反复验证的配方 | "财报分析配方,用了 3 次,成功 2 次" | 成功率 >90% 且调用 >100 次→升级永久 |
| 资料摘要 | 最近看的论文、视频、网页关键信息 | "《Python 数据分析》提炼 20 条三元组" | 反复引用→升级永久;过期→归档 |
| 临时用户偏好 | 近期表现出的偏好变化 | "用户最近喜欢更短的回复" | 持续稳定→升级永久;短期波动→衰减 |
| 待验证三元组 | 置信度中等(60-85),需要更多证据 | "[新方法]—[可能]→[有效]" | 验证通过→永久;失败→丢弃 |
| 错误案例(error_case) | 最近犯过的错,避免重犯 | "[删文件]—[导致]→[系统崩溃]" | 反复出现→升级永久;不再出现→归档 |
| 情绪历史 | 最近的情绪波动记录 | "过去一周用户压力大" | 用于分析用户状态,**不升级永久** |
| 外部大脑效果 | 哪个 AI 在什么场景最有效 | "DeepSeek 擅长财报,GPT-5 擅长代码" | 稳定有效→升级永久 |
| 项目上下文 | 当前项目进度、文件、依赖 | "游戏完成 60%,AI 完成 40%" | 项目结束→归档或升级永久 |

### 2.3 永久记忆(Permanent Knowledge)—— 知识图

- 内容:已学习验证的知识、用户永久习惯与偏好、验证过的错误
- 结构:**三元组关系图**(主语 —[关系]→ 宾语),支持大类/小类层级
- 用途:检索命中后注入模型上下文,让模型"动态自我微调与学习"
  (实现方式 = 记忆检索 + 提示注入/RAG,**不修改模型权重**)
- 存储:`memory/permanent/triples.json`(图结构)+ 对应 `.md` 详情

## 3. 检索机制

1. **分词**:中文分词 + 英文分词,查询词与库内内容双向分词,提高召回准确度
2. **匹配优先级**:原词 > 同义词 > 错别字容错(编辑距离/拼音)> 相近词语义匹配
3. **图扩展**:命中三元组后,沿关系边扩展一圈(大类 → 小类)
4. **排序**:置信度 × 引用次数 × 时间衰减

## 4. 存储格式:双文件制

- `{名称}.md` —— **全部详细信息**,人类可读、可手改
- `{名称}.json` —— 机器可读的重要信息:时间、来源、任务分类、关联(双链/三元组/所属记忆层)
- 笔记与记忆"像关系图一样"互相引用,一层文件即一层图节点

目录草案:

```
vault/
├── notes/            # 普通笔记,xx.md + xx.json 成对
├── memory/
│   ├── short/        # 短期:会话快照(按 session_id)
│   ├── long/         # 长期:9 类条目分文件夹
│   └── permanent/    # 永久:triples.json + 已验证知识 .md
├── attachments/      # 附件(二期)
└── config.json       # 端口、Token、黑名单、衰减参数
```

## 5. 前端(对标 Obsidian)

- 三栏布局:左侧文件树/标签 | 中间 Markdown 编辑/预览 | 右侧面板
- **关系图视图**:力导向图,短期/长期/永久分层着色,大类/小类聚簇
- **记忆面板**:浏览三层记忆条目、置信度、引用次数、升降级流水
- Ctrl+P 命令面板、`[[双链]]` 跳转、反链面板(对标 Obsidian 标志交互)
- 全局搜索框:走第 3 节检索机制(分词 + 容错)

## 6. MCP Server(对外 AI 接口,设计定稿)

- 形态:笔记软件内嵌 MCP Server(参考 Obsidian MCP 生态),**Mindbox 不是 agent**
- 传输:Streamable HTTP,`http://127.0.0.1:{port}/mcp`,JSON-RPC 2.0
  (initialize / tools/list / tools/call / ping,纯 JSON 响应,无推送需求,不引 SDK)
- 鉴权:Bearer Token(vault/config.json 的 `token`,为空则本地免鉴权)
- 安全:仅绑定 loopback、路径黑名单、会话用量统计
- 实现原则:与 REST 共用同一服务层(services/),MCP 只是另一层皮
