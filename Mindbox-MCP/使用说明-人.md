# 使用说明(给人看)

> Mindbox-MCP · 三层记忆外部大脑 · 版本 1.0.0
> 位置:`/media/fuka/萤捷/Mindbox-MCP`(D 盘根目录)
> 零依赖:只用 Python 3 标准库,不需要 pip 安装任何东西。

---

## 1. 这是什么

一个**独立的 MCP 服务**:把它接进任何一个支持 MCP 的 AI 客户端(Trae、Cursor、
Claude Code、CodeBuddy 等),AI 就有了一套**跨会话的记忆**。

它本身不是 AI,只是"记忆库 + 工具"。AI 通过工具往里写、往外读,于是:

- 这一次聊的东西,下次它还"记得";
- 踩过的坑会被记成**错误案例**,不容易重犯;
- 学到的事实会沉淀成**三元组知识图**,越用越懂你。

它的核心是**三层记忆**,对应三个文件夹,它们是系统自带的,**不可删除**。

```
├── mcp.json                 # 接入配置模板(直接复制粘贴用)

│   └── <agent>/<会话>/       #    每个 agent 的每个会话一个文件夹
│       ├── 会话.json         #    机读快照:摘要/任务/待办/结论/上下文
│       └── 上下文.md         #    人读版:同样内容的 Markdown
│
├── 长期记忆/                 # ⛔ 系统自带,不可删除
│   ├── 任务记录/             #    9 类条目,按分类分文件夹
│   ├── 技能配方/
│   ├── 资料摘要/
│   ├── 用户偏好/
│   ├── 待验证三元组/
│   ├── 错误案例/
│   ├── 情绪历史/
│   ├── 外部大脑效果/
│   └── 项目上下文/           #    每个条目一个 .json
│
└── 永久记忆/                 # ⛔ 系统自带,不可删除
    ├── triples.json          #    三元组知识图(主语—[关系]→宾语)
    └── <条目>.json           #    已验证的永久条目
```

### 关于"不可删除"

- MCP 工具层面**没有删除这三个文件夹的能力**,只能增删文件夹里的单条记忆。
- 服务每次启动、每次调用前都会校验这三个文件夹,缺了就**自动重建**。
- ⚠️ 注意:本盘是 **exfat**,Linux 的文件权限(包括 `chattr +i` 只读锁)在它上面
  不起作用。所以"不可删"是**程序级保护**:你用资源管理器手动删,程序管不了,
  但**下次启动会自动重建**(内容会丢)。真的不想丢,就定期备份。

## 3. 三层记忆怎么分工

| 层 | 干什么 | 什么时候写 | 生命周期 |
|---|---|---|---|
| **短期记忆** | 当前会话的"状态快照":摘要、任务进度、待办、中间结论 | 会话开始 / 每完成一步 / 会话结束 | 会话内,结束后冻结;有价值的内容转长期 |
| **长期记忆** | "可能有用"的过渡资料 + 9 类条目,带置信度与来源 | 学到新东西、发现偏好、犯错 | 证据充分后以 ≥85 置信度写成三元组,进永久 |
| **永久记忆** | 已验证的知识与三元组关系图,越用越准 | 高置信度事实(≥85) | 长期 |

**置信度(0-100)是这套系统的关键:**

- `≥ 85`:证据充分 → 直接进**永久**知识图
- `60 ~ 84`:有点像但不确定 → 进**长期 · 待验证三元组**
- `< 60`:证据不足 → **拒收**

## 4. 怎么接入(任选你的客户端)

### 4.1 通用配置

所有客户端认的都是同一段配置,内容在 `mcp.json` 里:

```json
{
  "mcpServers": {
    "mindbox-memory": {
      "command": "/media/fuka/萤捷/Mindbox-MCP/run-mindbox-mcp",
      "args": [],
      "env": {}
    }
  }
}
```

### 4.2 Trae

设置 → MCP → 添加服务器 → 选"手动配置 / 粘贴 JSON" → 把 `mcp.json` 的内容贴进去 → 保存。
连接成功后,工具列表里会出现 `mindbox-memory` 及其 9 个工具(全部围绕"开任务 → 记进度 →
沉淀知识 → 检索复用"这一条真实主线,无冗余)。

### 4.3 Cursor

把同样的 JSON 合并进 `~/.cursor/mcp.json`(或项目里的 `.cursor/mcp.json`),重启 Cursor。

### 4.4 Claude Code / CodeBuddy Code CLI

```bash
claude mcp add-json mindbox-memory "$(cat '/media/fuka/萤捷/Mindbox-MCP/mcp.json')"
# 或直接编辑项目根目录的 .mcp.json,写入上面那段配置
```

### 4.5 先自己验证一下(不接客户端)

```bash
python3 "/media/fuka/萤捷/Mindbox-MCP/server.py" --check
```

输出里能看到服务器名、工具数量和三层记忆的当前条目数,说明服务是好的。

## 5. 接入之后怎么用

不需要你写任何命令,AI 会自己调工具。你只要正常说话:

| 你说 | AI 应该做的事 |
|---|---|
| "记住:我的项目路径在 /x/y" | `memory_add` 写入长期记忆(用户偏好/项目上下文) |
| "上次那个 bug 怎么修的?" | `memory_query` 检索,命中即读 |
| "从现在起我们做个长期项目" | `session_open` 建短期记忆 → 每步 `session_update` |
| "今天先到这" | `session_close`,把结论转长期记忆 |

**你可以直接要求它**:"把这条写进永久记忆"、"查一下我的记忆里有没有关于 XX 的",
"这个结论置信度还不够,先放长期待验证"。

### 手工查看 / 修改

所有记忆都是**普通文件**,随时可以自己打开看、改、删:

- 想看看 AI 记了什么 → 直接进 `短期记忆/` `长期记忆/` `永久记忆/`
- 想纠正一条记忆 → 打开对应 `.json` 改内容后保存,MCP 下次读到就是新的
- 想清空某一层 → 删掉里面的条目文件即可(别删三个根文件夹)
- `上下文.md` 是给 AI 看的 JSON 的**人读镜像**,改它不影响数据(以 `.json` 为准)

## 6. 常见问题

**Q:会不会占很多空间?**
每个条目就是一个几 KB 的小 JSON。除非你几万条,否则忽略不计。

**Q:多个 AI 客户端能同时用吗?**
能。短期记忆按 `<agent>/<会话>` 分开存,互不干扰;长期/永久是共享的,谁都能读写。

**Q:AI 会不会乱写、写垃圾进去?**
对不确定的东西,置信度低会被拦在长期待验证区或直接拒收。而且内容全是明文文件,
你随时能删能改。

**Q:怎么备份?**
整个 `Mindbox-MCP` 文件夹复制一份就行。
**注意**:备份到 exfat/NTFS 时无法用软链接,直接复制文件夹即可。

**Q:怎么彻底重置记忆?**
删掉三个根文件夹里的内容,**保留**三个根文件夹本身(或者干脆让程序下次启动重建),
然后重启客户端。

**Q:为什么只有 9 个工具?**

工具越多,AI 越容易选错、越浪费上下文。所以只保留真实任务闭环需要的那几个,
凡是能被替代或有更好入口的一律去掉:

| 已移除 | 原因 |
|---|---|
| `session_read` | `session_open` 续接时会直接返回已有快照 |
| `session_append` | `session_update` 的 `context` 字段已覆盖 |
| `session_list` / `memory_list` | 你在文件管理器里看文件夹更直观 |
| `memory_get` | `memory_query` 返回的就是完整条目 |
| `memory_hit` / `memory_promote` | 依赖"引用 >100 次"的晋升门槛,实际用不到;等自动升降级上线再恢复 |
| `report_error` | 它就是 `memory_add(category="error_case")` 的薄封装 |

**Q:AI 说"工具调用失败 / 找不到命令"怎么办?**
1. 跑一次 `python3 .../server.py --check`,看是否报错;
2. 确认 `run-mindbox-mcp` 有可执行权限(`chmod +x`);
3. 确认客户端配置里 `command` 是**绝对路径**;
4. 客户端需要**重启**才会加载新 MCP。

## 7. 一句话总结

把 `Mindbox-MCP` 当成 AI 的"外挂硬盘":短期记忆是便签纸,长期记忆是资料柜,
永久记忆是刻在石头上的结论。你负责用,它负责记。
